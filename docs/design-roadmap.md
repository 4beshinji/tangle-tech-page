# Tangle Tech デザイン・コンテンツ方針

> 2026-07-17 全面改修後の正本。旧「Computational Editorial / Autonomous Systems Studio」方針は廃止した。

## ブランドの核

Tangle Tech は、工場のように設備と作業が高密度に集約された場所ではなく、農場や都市のように対象が薄く広く分散する環境を扱う。

中核は次の3要素。

1. 植物群落の生理・成長モデル
2. 分散エッジと安全な自律制御
3. HR・労務・同意・承認・監査

製品構造は `Auto JA = ほ場` と `farm-ops = 人` の2系統。その他のプロジェクトは、共通アーキテクチャを別領域で検証する技術デモとして扱う。

## 情報設計

トップページは次の順序を維持する。

1. 何を知能化するか
2. 集約型と分散型の違い
3. 観測から学習までの閉ループ
4. Auto JA / farm-ops の責務
5. 研究実装の成熟度
6. 技術デモ
7. 現場観測から始めるCTA

中核システムと技術デモを同列に並べない。抽象的な「異分野統合」やAIそのものを価値提案にしない。

## コピーの原則

- 技術名だけでなく、何を入力し、何を判断し、何を操作するかを書く
- 実装済み、ベンチ実装、現地検証、設計のみを区別する
- 現地実証前の機能を運用実績として書かない
- LLMが高速制御を担うような誤解を避け、決定的制御との権限境界を書く
- farm-ops の正式名称と農場法人向けの定位を使用し、旧NUAI定位へ戻さない
- 「革新的」「最大のリターン」「寄り添うAI」など根拠のない形容を使わない

## ビジュアルの原則

- deep green、mineral white、chlorophyll green を中心にする
- ノード、経路、空間グリッド、時系列、状態表示を情報図として使う
- 写真や生成画像は、実際の現場・装置を示す必要がある場合だけ使う
- 紫系グラデーション、抽象ニューラルネット、ロボット、sparkleを使わない
- 汎用SaaSカード、過剰な角丸、中央寄せの抽象ヒーローを避ける
- モーションは状態変化の説明に限定し、`prefers-reduced-motion` を尊重する
